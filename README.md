# Northwind Catalog Extension

Private-extension-style catalog migration helper for the Fynd Technical Implementation Manager case study.

The project reads Northwind Apparel's messy legacy catalog export, normalizes and validates products, expands size variants, reports invalid rows clearly, and prepares product-create payloads for Fynd's Platform Catalog API.

## What is included

- Sample legacy export: `data/northwind_legacy_export.json`
- Transformer and validator: `src/normalizer.js`
- Rate-limited, checkpointed migration runner: `src/ingest.js`
- FDK route adapter for a private extension: `src/extension-routes.js`
- Boltic/serverless HTTP function entrypoint: `serverless/boltic.js`
- CLI for validation, dry-run payload generation, and live ingest: `bin/catalog-migrate.js`
- Tests for duplicate SKU, missing fields, malformed row, dirty price, bad image URL, and variant splitting
- Part B solutioning write-up: `docs/part-b-solutioning.md`

## Assumptions

- Northwind's legacy export can arrive as JSON, JSONL, or CSV. The provided sample is JSON because it lets each row use different legacy field names.
- A normalized product maps to Fynd's `Others` category and `Supplementary` template as requested in the brief.
- One valid product produces one catalog create request. Size variants are included in the product payload.
- The exact product payload may need minor adjustment after Fynd template validation, especially if the development company enforces additional HSN, tax, department, or attribute rules.
- Live ingestion requires a Fynd Partners account, development company, private extension, and valid Platform API credentials. Those cannot be created safely from this local workspace.

## Setup

```bash
npm install
```

Node 18+ is required. Fynd's extension setup docs also require Git, Node 18+, a Fynd Partners account, and a development company.

## Run validation

```bash
npm run validate
```

Expected sample result:

```text
Total rows:     12
Valid products: 5
Invalid rows:   7
Warnings:       0
```

The report is written to:

- `reports/validation-report.json`
- `reports/validation-report.md`

## Generate Fynd payloads without calling Fynd

```bash
npm run dry-run
```

This writes:

- `reports/fynd-product-payloads.json`
- `reports/validation-report.json`
- `reports/validation-report.md`

No API call is made in dry-run mode.

## Boltic serverless usage

Deploy either root `index.js` or `serverless/boltic.js` as a Node.js 18+ HTTP function. Use handler name `handler`.

If the platform asks for a single handler string, use:

```text
index.handler
```

The function accepts `POST` JSON bodies in either of these forms:

```json
[
  {
    "Product Name": "Everyday Cotton Tee",
    "SKU": "NW-TSH-001",
    "size variants": "S/M/L",
    "MRP": "₹1,299.00",
    "Image URL": "https://example.com/northwind/everyday-cotton-tee.jpg"
  }
]
```

or:

```json
{
  "action": "dry-run",
  "rows": []
}
```

Supported actions are `validate`, `dry-run`, `preview`, and `ingest`.

Live ingestion is deliberately opt-in:

```json
{
  "action": "ingest",
  "live": true,
  "rows": []
}
```

Set Fynd credentials as Boltic environment variables, not in the request body:

```text
FYND_COMPANY_ID
FYND_API_KEY
FYND_API_SECRET
FYND_DOMAIN
```

For deployment details and request/response examples, see `docs/boltic-serverless.md`.

Local smoke test:

```bash
npm run serverless:smoke
```

## Private Fynd extension flow

1. Create or log into your Fynd Partners account.
2. Create/select a development company.
3. Install the FDK CLI:

   ```bash
   npm install -g @gofynd/fdk-cli
   ```

4. Log in and scaffold a private extension:

   ```bash
   fdk login
   fdk extension init
   ```

5. Choose `Private` as the extension type. Fynd recommends the `Node + React.js + SQLite` template.
6. Copy this repo's `src`, `bin`, `data`, `docs`, and `test` folders into the generated extension, or keep this repo as the extension service code if the scaffold allows it.
7. Register the route adapter from `src/extension-routes.js` in the server entrypoint generated by FDK:

   ```js
   const { registerNorthwindCatalogRoutes } = require("./src/extension-routes");
   registerNorthwindCatalogRoutes(fdkExtension);
   ```

8. Preview/install the extension:

   ```bash
   fdk extension preview
   ```

## Live ingestion

For local CLI ingestion, set credentials:

```bash
export FYND_COMPANY_ID="your-development-company-id"
export FYND_API_KEY="your-api-key"
export FYND_API_SECRET="your-api-secret"
export FYND_DOMAIN="https://api.fynd.com"
```

Then run:

```bash
npm run ingest
```

The ingest runner respects the 100 requests/minute limit and writes a checkpoint to `reports/ingest-checkpoint.json`, so an interrupted run can resume without recreating already successful products.

If the SDK method name or payload schema differs in your Fynd company, set `FYND_PRODUCT_ENDPOINT` or adapt `src/fynd-client.js`. The adapter already tries `platformClient.catalog.createProduct({ body })` first, then falls back to `platformClient.request(...)`.

## Evidence to capture

After a live run, place proof in `evidence/`:

- Screenshot of the created products in the Fynd development company
- API response JSON from a successful create call
- Validation report showing rejected duplicate/missing/malformed/bad-image rows

See `evidence/README.md` for the exact checklist.
