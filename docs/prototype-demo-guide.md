# Prototype Demo Guide

This guide explains what the serverless prototype does, what the downloadable extension contains, and exactly what happens when you click **Dry Run**.

## What This Prototype Is

The project is a catalog migration prototype for the Fynd TIM case study. It demonstrates how messy legacy catalog rows can be cleaned, validated, converted into Fynd-style product payloads, and reviewed before any live product creation happens.

It has two demo surfaces:

- A Boltic serverless web page served from `handler.js`.
- A downloadable Chrome-compatible extension ZIP generated by the same serverless handler.

Both surfaces call the same serverless actions:

- `validate`
- `dry-run`
- `ingest`

In the Boltic single-file prototype, `ingest` is intentionally dry-run only. It does not call Fynd APIs or create products.

## Why It Is Named Northwind

The assignment brief used Northwind Apparel as the legacy merchant/catalog example. The prototype keeps that name so the code, sample data, reports, and demo match the case-study wording.

## What Dry Run Does

Dry Run is a safe simulation of the catalog migration. It performs the transformation and validation work, creates the payloads that would be sent to Fynd, and returns a fake success result for each valid product.

Dry Run does not:

- Call Fynd.
- Need Fynd OAuth.
- Need API keys.
- Create products.
- Modify any catalog data.

Dry Run does:

1. Reads the JSON rows from the page, extension popup, or request body.
2. Accepts either a raw array or an object with `rows`.
3. Maps messy legacy field names to standard fields.
4. Normalizes SKUs by trimming, uppercasing, and replacing spaces with hyphens.
5. Parses prices from values like `INR 1299`, `Rs. 1399`, or numeric values.
6. Detects currency from symbols or explicit currency fields.
7. Splits size variants such as `S/M/L` into `["S", "M", "L"]`.
8. Validates required fields:
   - product name
   - SKU
   - size variants
   - valid positive price
   - absolute `http` or `https` image URL
9. Detects duplicate SKUs within the submitted rows.
10. Separates valid products from invalid rows.
11. Builds Fynd-style product payloads for valid products.
12. Returns a simulated ingestion summary where each valid product is marked `success`.

The response includes:

- `summary`: total rows, valid products, invalid rows, warning count.
- `invalidRows`: rejected rows with error codes and messages.
- `warnings`: non-blocking warnings.
- `payloads`: Fynd-style product-create payloads.
- `ingestion`: dry-run success summary.

```json
{
  "summary": {
    "total_rows": 3,
    "valid_products": 1,
    "invalid_rows": 2,
    "warning_count": 0

```

## Field Mapping

The transformer accepts several legacy names for each required product field.

| Normalized field | Accepted legacy field names |
|---|---|
| `name` | `Product Name`, `name`, `title`, `item_name`, `product_title` |
| `sku` | `SKU`, `sku_code`, `item code`, `seller_identifier`, `item_code` |
| `brand` | `brand`, `Brand Name`, `manufacturer` |
| `sizes` | `size variants`, `sizes`, `available_sizes`, `size`, `variant_sizes` |
| `price` | `price`, `MRP`, `selling_price`, `list price`, `list_price`, `marked_price` |
| `currency` | `currency`, `currency_code` |
| `imageUrl` | `Image URL`, `image_url`, `imageurl`, `image`, `primary_image` |
| `description` | `description`, `desc`, `long_description` |
| `color` | `color`, `colour` |
| `gender` | `gender` |
| `department` | `department`, `category` |

Defaults used by the prototype:

| Field | Default |
|---|---|
| `brand` | `Northwind Apparel` |
| `department` | `Apparel` |
| `category_name` | `Others` |
| `template_name` | `Supplementary` |
| `currency` | `INR` |

## Serverless Preview

Local preview:

```bash
node -e "const http=require('node:http'); const handler=require('./handler').handler; const server=http.createServer(async (req,res)=>{let body=''; req.on('data',c=>body+=c); req.on('end',async()=>{const response=await handler({method:req.method,url:req.url,headers:req.headers,body}); res.writeHead(response.statusCode,response.headers); res.end(response.isBase64Encoded?Buffer.from(response.body,'base64'):response.body);});}); server.listen(3017,'127.0.0.1',()=>console.log('preview http://127.0.0.1:3017'));"
```

Open:

```text
http://127.0.0.1:3017/
```

Demo actions:

- **Dry Run**: returns Fynd-style payload preview and simulated ingestion summary.
- **Validate**: returns only validation and normalized product output.
- **Sample**: reloads the included sample rows.
- **Clear**: clears input/output.
- **Download Prototype Extension**: downloads the Chrome extension ZIP.

## Downloadable Extension Preview

The serverless page generates:

```text
northwind-catalog-extension-prototype.zip
```

The ZIP contains:

| File | Purpose |
|---|---|
| `manifest.json` | Chrome extension manifest v3 |
| `popup.html` | Popup interface |
| `popup.css` | Popup styling |
| `popup.js` | Calls the serverless `/validate` and `/dry-run` endpoints |
| `sample-data.json` | Sample messy catalog rows |
| `extension.config.json` | Generated endpoint configuration |
| `README.md` | Demo instructions inside the ZIP |

To preview:

1. Unzip `northwind-catalog-extension-prototype.zip`.
2. Open `chrome://extensions`.
3. Enable **Developer mode**.
4. Click **Load unpacked**.
5. Select the unzipped `northwind-catalog-extension-prototype` folder.
6. Open the extension popup.
7. Click **Dry Run** or **Validate**.

## Serverless Endpoints

| Endpoint | Method | Purpose |
|---|---|---|
| `/` | `GET` | Browser demo UI |
| `/health` | `GET` | JSON health metadata |
| `/validate` | `POST` | Validate and normalize rows |
| `/dry-run` | `POST` | Validate, build payloads, simulate ingestion |
| `/ingest` | `POST` | Dry-run only in the single-file Boltic prototype |
| `/extension-package` | `GET` | JSON metadata plus base64 ZIP |
| `/download` | `GET` | Direct ZIP download |

## Request Shape

Send either a raw array:

```json
[
  {
    "Product Name": "Everyday Cotton Tee",
    "SKU": "NW-TSH-001",
    "size variants": "S/M/L",
    "MRP": "INR 1299",
    "Image URL": "https://example.com/northwind/everyday-cotton-tee.jpg"
  }
]
```

Or an object:

```json
{
  "action": "dry-run",
  "rows": [
    {
      "Product Name": "Everyday Cotton Tee",
      "SKU": "NW-TSH-001",
      "size variants": "S/M/L",
      "MRP": "INR 1299",
      "Image URL": "https://example.com/northwind/everyday-cotton-tee.jpg"
    }
  ]
}
```

## Limitations

- The serverless prototype does not perform live Fynd product creation.
- No Fynd OAuth is required for this prototype.
- The single-file `handler.js` duplicates the core transform logic because Boltic code publish deploys the handler source directly.
- Real ingestion should be done only after Fynd credentials, development company, category/template validation, and API permissions are confirmed.
